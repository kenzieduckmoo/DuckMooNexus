# Crafting Desk: personal RTM completion plan

Updated October 19, 2026. Authority: ../Crafting Desk chat update.txt and the user's character-order reply. This plan replaces the former priority order, not unfinished requirements. Implementation progress lives in EXECUTION-LEDGER.md. Historical implemented behavior is preserved in VERIFIED-BASELINE-2026-10-19.md; its tests are prior results, not fresh verification.

## Finish line

RTM means the personal local app and capture addon support the complete workflows below, with saved user data preserved, regression checks passing, an actual in-game capture/reopen/reload/import check, and laptop access verified. Existing profession guides must remain usable; further route optimization is explicitly deferred. A missing required external verification keeps RTM pending even if implementation is finished. No public hosting, public-user hardening, proof of globally optimal leveling, or new secondary-profession work is required. Use milestones rather than promising a calendar date before measuring scan behavior.

## Implementation order

1. **Measure capture behavior and establish the shared calculation contract.** Record why scans start/reset, query counts and reopen behavior. Trace existing candidate, product, quality, inventory, concentration and cooldown models before adding another system. Establish one batch evaluator for both crafting screens. Preserve separate with/without-concentration reagent choices. Define best crafter as the feasible candidate with the highest total net profit for the requested craft count and selected mode. Show purchase cost separately from the value of all consumed materials; owned materials do not become free profit. Unknown sale prices cannot establish profit. Never silently reduce a requested batch.
2. **Fix capture reuse and invalidation.** Use measured causes to implement bounded reuse/resume and persistent caching where valid. Retain completed records while replacements are collected. Invalidate affected results for relevant recipe, profession skill, specialization, equipment, buff, build and schema changes; transient unavailable APIs must not cause an unconditional full rescan. A single recipe probe is not sufficient proof that every specialization-dependent result is unchanged. Verify close/reopen, reload, unchanged events, real stat changes, newly learned recipes and partial scans. Remove obsolete capture work only after tracing consumers. A wholesale rewrite is justified only if measured behavior requires it.
3. **Finish Crafting & Profit.** Replace the workshop with a clear item → requested craft count → recommended crafter flow. Show each product once, with quality variants inside its details and distinct item identities preserved. Display output amount, selected reagent qualities, total materials, available stock, missing purchases, purchase cost, full material cost and net batch profit. Keep concentration and ordinary crafting distinct. Retire implementation-facing Setups terminology and unnecessary warnings, migrating existing saved choices instead of deleting them. Preserve shortlist filters and shared-stock reservations. Complete the existing recipe-investment acquisition/shopping path: >20% margin, >0.1 sale rate, recipe acquisition price/currencies, payback and usable purchase instructions. Reference-crafter results must not masquerade as an unlearned character's performance.
4. **Finish Concentration Ready.** Include professions below cap using projected current concentration minus reservations. Group professions within each character in the supplied order. Rank the affordable repeated-recipe batch by total net profit, not profit per concentration or per craft. Respect known cooldowns, independent profession pools, shared inventory and existing plans. Show materials and exact-quality Auctionator copy/export actions with the recommended batch. Expose useful filters without requiring a trip to another tab. When no option qualifies, show the actual reason. Compute an availability time only for a known concentration or cooldown shortage; absent prices, missing captures or failed profit filters do not have an invented timer.
5. **Enable laptop use on the home network.** Configure the launcher and server together for LAN access while retaining localhost. Display the host address and port. Ensure imports, plan saving and copy/export work from the laptop, including origin handling for the actual configured address. Game data stays on the desktop. No router forwarding or public hosting. Verify desktop reads/writes automatically; actual laptop access is a separate release gate. Document any concrete firewall step if required.
6. **Reconcile and ship the personal RTM build.** Remove obsolete controls and unused paths after checking dependencies. Reconcile README and addon instructions with actual behavior. Run focused regressions plus end-to-end craft, concentration, shopping and import checks using current snapshots without overwriting user plans. Validate primary-profession guide skill resume, stock accounting, purchases, checkpoints and exports; fix regressions but do not resume optimization. Package a versioned addon ZIP if changed. Record remaining genuine limitations and all verification in the ledger. GitHub publication is not implied.

## Profession Guides: deliberately paused work

Defer deeper route searches, new optimization algorithms, expanded recipe-source coverage and uncertain skill-up probability modeling until other priorities are complete or the user requests them. Cooking and all secondary-profession development are excluded for now; preserve existing data.
