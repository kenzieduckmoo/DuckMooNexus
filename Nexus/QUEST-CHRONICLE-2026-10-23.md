# Character quest chronicle — October 23, 2026

Character sheets now use an independent completed-quest component under Progress. It offers source selection between Blizzard API and retained Omni Capture lists, picks the newest known observation by default, searches known quest titles or IDs, deduplicates IDs and progressively renders large lists. Names can be enriched from the character's public API records and retained turn-in events; source membership is never inferred from names or merged into an artificial union. Unknown titles stay labeled by ID. Captured-empty, partial, unavailable-with-retained-data and absent sources remain distinct.

A separate recent-turn-in section queries up to 40 retained Omni quest-completion events from PostgreSQL history, not just the current addon queue. It shows observed turn-in times and captured gold/XP rewards, with search and incremental display. The rewards are not presented as patron-order commissions or cost-adjusted profit. Existing character-page freshness polling continues to refresh these sections when source revisions change.

The receipt bridge's first real journal identity upload exposed an important legacy boundary: unvisited profiles recovered from old logout events must stay valid after those events leave the addon queue. Normalizer 0.1.3-omni3 reuses only a previously proven recovery for the same character and discarded logout timestamp. Historical raw archives and event records stay intact. Migration 017 lets the current Omni view read the new adapter version. The focused capture regression includes matching and mismatched archived recovery cases.
