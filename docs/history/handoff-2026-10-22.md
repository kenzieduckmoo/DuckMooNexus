## 5. Architecture and source-code map

Intended three layers: immutable raw archives → normalized records with provenance → derived views/dashboards. Source event time, file save time, collection/import time and API server update time are distinct.

0.4.0 inspected flow:

```text
WoW addon SavedVariables / TSM AppData
  → collect_sources.py + snapshots.py
  → local gzip + manifest + deterministic bundle
  → Sync-Nexus.ps1, restricted SSH put HASH SIZE
  → receiver.py validates/stores packet under global lock
  → Docker service.py ingest
  → archive commit, then supported adapter normalization
  → Journalator-specific importer when source is Journalator.lua
  → receipt returned; Windows logs result
  → PostgreSQL views → provisioned Grafana panels
```

The 0.4.0 receiver imports synchronously. Do not describe it as the old asynchronous v0.2.0 worker queue. It accepts only `put SHA256 SIZE`; the original receiver's `status HASH` and v0.3.0 `put2` protocol are different generations.

## 6. Source coverage and economic semantics

The source allowlist contains 15 SavedVariables sources plus `TSM_AppData`. Missing files are skipped; discovery does not mean every source was present or normalized.

| Source | Implemented interpretation | Boundary |
|---|---|---|
| Journalator | Raw archive plus decoded event transactions | Not inventory cost basis or complete realized profit |

| Syndicator | Cached bank and character money | Observation time unknown; file save time is not the money sample time |
| DuckMooWarband | `activity.bank` sample | Legacy unvalidated API sample, including possible zero; not preferred bank ledger |
| Auctionator | Daily history extrema/availability and cached quotes | Not sale counts; cache lacks source observation time |
| TSM actual AppData | Downloaded market/sales estimates with dataset timestamps | Estimates remain estimates; only selected metrics normalized |

| Journalator_Statistics, DuckMooFolio, DuckMooPlanner, WarbandNexus, TradeSkillMaster, TradeSkillMaster_AppHelper SavedVariables, CraftSim, AllTheThings, WoWthing_Collector | Raw preservation in supplied implementation | Dedicated full normalization is unfinished |

Journalator uses Archivist `LibDeflate:DecodeForPrint → DecompressDeflate → LibSerialize:Deserialize`. The data-only parser rejects executable expressions and malformed/unsupported inputs. Empty stores and observed version differences matter. Original identity `[namespace, store_id, category, ordinal]` preserves legitimate identical events in different positions; conflict detection must not silently rewrite history. Do not reuse this append-position model for overwriting Capture previews.

WarbandAccountant ledger indices shift on prepend. Its adapter uses canonical payload hash plus multiplicity and preserves snapshot order, including same-second entries. Internal deposits/withdrawals are balance evidence, not new income. Do not count a transfer between characters and bank twice.

Financial views include invoice/fee, vendor, quest/cache, order commission/cut, repair, training, taxi and postage components. Deposit principal, ambiguous mail/trade money, own-reagent costs, lost-deposit attribution and patron enum interpretation remain unresolved or separately labelled. “Auction trade net,” “recorded flow,” “revenue” and “profit” are not interchangeable.

Auctionator history fields were interpreted from installed addon source as lowest-low/highest-low/peak availability. Preserve realm and item variant identities. Supply disappearing between Blizzard snapshots is reduced observed supply, not proven sales: cancellation, expiration and relisting remain possible.

I'd use three levels of data storage.

Layer	Purpose

Raw archive	Preserve original source snapshots or event files, compressed and timestamped

Normalized database	Extracted records with consistent character, item, event, and timestamp identifiers
